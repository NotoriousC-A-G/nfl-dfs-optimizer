## Revision 2 — expert challenge of Revision 1 (football + model-analytics, 2026-10-07)

Football: **pushback (b) no forced correlation — signed off** (keep the one required QB+pass-catcher stack); **D1 pivotal questions — conditional sign-off** on the guardrails below; **D7 not signed off for Chalk Pivot and Volume Anchor** until each has a measurable differentiator. Model-analytics: **withholds D2/D3/D4 as written; D4 approved after the two fixes below.** Accepted changes:

1. **Pivotal-question guardrails (football).** Hard cap of 2 independent questions per game; a 3rd only as a *child* of the first. Each question must carry: a metric from a fixed pbp-computable menu (sack/QB-hit rate, pass rate over expected when leading, lead-at-Q4 flag, pace, rush EPA, explosive-pass rate — no time-to-throw/participation proxies, which don't exist for 2026), the packet source field, a threshold, a direction, and the sample size (≥ ~25 dropbacks for rate stats). The two questions must concern *different units or phases* (not both "does the offense score"). Every stated dependency names its causal channel and must move P(B|A) vs P(B|¬A) by a stated minimum or it is dropped. Include a **residual branch ("neither resolves as framed") ≥ 10%** and an **"indeterminate" outcome excluded from grading**. Thresholds for collapse/pressure branches must sit at ≥ the 60th percentile of the league distribution (code prints the percentile). Each question states "what this adds beyond the line".
2. **Probability model (model-analytics).** Two binary questions → joint with 3 numbers (p1, p2, one dependency λ restricted to {−0.5, 0, +0.5}, graded as a diagnostic only). Anchor marginals to **reference classes** (e.g. "OL holds" = team sack+QB-hit rate vs the 75th percentile → base rate 0.25, shifted by unit grades/starters out), not to the line. **LLM shift cap ±0.25 log-odds** (was ±0.5 — a 0.5 shift is indistinguishable from the anchor for months); probabilities in 5-pt buckets; log anchor and adjusted values.
3. **"Mix reproduces the line" check, rebuilt (it was nearly vacuous).** Build the constraint in: `E[margin|b] = M_line + a1(q1−p1) + a2(q2−p2) + a12(q1−p1)(q2−p2)`; code checks `Σ p_b·m_b = M_line` (and the total) to rounding, and bounds branch shifts (flag |a| > 8). Tolerance: **±1.0 pass band, ±2.0 hard fail** (market-mean uncertainty, not the 13-pt outcome SD). Real disagreement with the line is allowed only as an explicitly *declared* `d`, |d| ≤ 2 points, graded separately. Off-tolerance fails loudly (no silent renormalizing).
4. **Tail value fixed (model-analytics: summing q90s was a bug — it treats the nine players as perfectly correlated and over-rewards volatility ~3×).** `TV_i = μ_i + c·(q90_i − μ_i)` with **c ≈ 0.33 (1/√9)**, and q90 from a **parametric gamma/lognormal per position×salary cell** (a q90 from ~17 games is a ~15th order statistic with huge SE), not an empirical quantile. The required stack enters as a small variance bonus (QB–WR ρ ≈ 0.35–0.4 ≈ +1.8 pts of lineup q90; bring-back ≈ +0.8; QB vs opposing DST ≈ −0.2). Branch multipliers still draft/unvalidated.
5. **Branch-vector rescoring (replaces the "deterministic proxy").** For each agent's top ~50 candidate lineups: draw ~2,000 branch vectors (sample each touched game's branch from p_b), apply branch multipliers to means, add independent residuals plus the QB–pass-catcher ρ, compute P(total ≥ T) with T from ResultsDB contest scores, and rank by it (~25 lines of numpy; handles partial correlation through the shared branch factor). This is a Monte Carlo over branch vectors — **not** the deferred scenario-tree simulator; D12 says so explicitly.
6. **Correlation sign rules (football), as analyst output + a code lint.** The analyst states sign and strength (strong/mild) per pair: QB vs opposing DST — negative (forbidden unless the thesis says otherwise); QB + own DST — weak positive, allowed not forced; favorite RB vs own pass catchers in a blowout — mildly negative (soft penalty); RB + own DST — positive; RB vs opposing DST — negative (penalize, don't ban, PRD §7); bring-back only when the sign is stated (total ≥ ~48 and opposing top receiver share ≥ 25%), otherwise skip; two RBs same team — negative; QB + same-team RB1 — neutral, not a stack. Do not require ≥ 3 players from a game; nothing forced in low-total games.
7. **Agent differentiators (football).** *Chalk Pivot*: holds the chalk game and excludes its top-3-owned QB/WR/RB, shares ≤ 4 players with Chalk Anchor. *Volume Anchor*: selected on volume metrics (carry/target/snap share), not projection; may use a low-total game. *Shootout Stack*: from the top ~2 games by total, QB + 2+ receivers + bring-back from one game. *Contrarian Game*: under-owned game with total ≥ 44. *Short Field*: only when a game has a named "one offense broken" branch ≥ 25% — otherwise it **fails loudly** (expected some weeks, consistent with the no-fallback rule). Cross-agent: ≥ 3-player difference between agents' lineups; ≤ 2 agents on the same game stack; the expert's pools must cite different branches. **Confirmed by Chris, 2026-10-07.**
8. **Grading corrections (model-analytics).** Grade pivotal-question probabilities against (i) the anchor and (ii) climatology using Brier (not log-loss); expect ~10–12 questions/week, not independent; **~100 questions minimum** (~9–10 weeks for a 0.2 true shift, ~35 weeks for 0.1) before any claim — so D12's "≥ 2 graded slates" gate and ADR-0046's matching criterion are replaced by "a pre-registered minimum of ~100 graded questions with a favorable paired Brier difference vs the anchor". Reliability tables need ~30/bin (not ~7 weeks). Proxy misclassification of 25–30% caps measurable skill. Log the questions the analyst did *not* choose (selection bias). The old backstop thresholds (1.15× line, 75th percentile, etc.) are arbitrary — state their base rates or drop them.
9. **Football's five wrong-story guardrails** become validator/prompt rules: cite replacement grade + snaps (injury effect as a range); "what this adds beyond the line" + code flag on beneficiaries above an ownership threshold; grade on opportunity (targets, red-zone touches), never fantasy points; thresholds can't be set to confirm the story (percentile printed, rejected below the 60th for collapse branches); every availability claim cites status + timestamp, incl. an injury beneficiary who is himself questionable.
10. **Football's corrections to its own v1 review:** defenses *do* shift to heavier run-stopping personnel when a passing game is failing — the interaction exists and runs through the pressure → pass-rate chain; its size must be measured, not asserted. The four buckets conflated "OL collapsed" with "defense forced turnovers" and merged two opposite-implication "offense broken" mechanisms (pass-protection collapse favors the opposing DST/rushers; a QB injury favors the opposing RB/short-field scoring).

## 0. What we are building, in one paragraph

A flag-gated pool pipeline that fails loudly (never silently substituting a lineup). Code builds a per-game **evidence packet**;
a **game analyst** (LLM) turns it into a **game thesis**: the game's pivotal questions and 2–4 **scenarios** (their combinations)
whose probabilities are anchored to the lines; an **expert** (LLM) picks **angles** and builds a **pool** (tiers + reasons + build
thesis) for each of the **six builder agents**; a code **validator** checks feasibility; the existing ILP maximizes **tail value**
inside each pool; everything is saved before kickoff so the post-mortem can grade it. Chalk Anchor (agent 1) is the baseline.
Friday output is a **forward experiment**, not a validated improvement.

## 1. Corrections to the evidence base (do not repeat the old claims)

- r = 0.46 projection↔actual is **normal** (trailing-mean r ≈ 0.28–0.39 on 2021–24). QB/TE r ≈ 0.14 is noise (SE ±0.13). The 3.6-pt top-decile gap is ~2.8 SE, in-sample, 2 weeks — regression to the mean, not proof of a broken model.
- The six agents are near-duplicates → effective n ≈ 1–2/week. A ~50-pt lineup miss ≈ 2 sd. "0 of 22 cashed" is weak evidence.
- What *is* solid: `bring_back_allowed` is **not** a hard constraint (scoring boost only); `ceiling_multiplier` is inert (98/629 populated, max ≈ 1.04); matchup grades ignore who is inactive; snapshot selection was buggy (fixed, #45); wk 3/4 operator projections were stale (fixed, #52/#53).
- Data corrections: nflverse injuries **already hold week-5 rows** for all positions (ADR-0031's "lags" premise is out of date) and nfl.com/injuries is plain scrapable HTML; **2026 participation data does not exist** (box counts/pressure/time-to-throw only from history); **no play-action column exists** anywhere in nflverse.

## 4. Grading and the A/B (performance-analytics + model-analytics)

- **Pre-register before kickoff:** primary metric = rank percentile of the best played lineup per week (+ total score). Diagnostics only: scenario Brier/log-loss **vs the line-implied anchor** (reliability tables not before ~100 game-scenarios ≈ 7 weeks), thesis-claim hits (graded only in the scenario that occurred, on opportunity numbers not fantasy points), core-tier hit rate vs base rate, exclude regret, Q decisions, angle outcomes (right scenario/wrong players vs wrong scenario).
- Scenario-hit rules fixed in advance (e.g. Shootout: total ≥ 1.15×line or both ≥ 24; Favorite pulls away: margin ≥ 14 and favorite wins; Grind: total ≤ 0.8×line and bottom-tercile pace; D: team pressure+sack rate ≥ 75th pct and pass EPA ≤ −0.15; else "none" — a high "none" rate means the set is incomplete).
- **Control:** old path (Chalk Anchor + at most one more old agent). Always-on baselines saved at generation time: chalk, projection-max, random feasible. Write-once artifacts; hash committed pre-kickoff; log divergence between generated and entered lineups.
- **Decision rules:** no winner and no drops before ~8 weeks or a pre-registered ≥ 2 SE loss; keep a component only if paired difference has the right sign in ≥ 70% of weeks and the pooled CI excludes 0; revise-not-drop when scenario layer and pool layer disagree. No ROI claims (one $1M-to-1st contest dominates variance). Week 5 is n = 1: it proves nothing statistically — say so in the output.
- Post-mortem extensions: scenario-grading table, angle outcomes, A/B block first; thesis-claim grading and pool regret list once structured claims exist. Replace the biased stack "hit = actual > projected" with the angle-conditional grade (keep as a secondary column). Add contest-type buckets to the season record.
